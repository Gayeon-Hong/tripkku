# 트립꾸 · 3D 캐릭터와 동선 재생 — 작업 정리 (다른 AI 인계용)

2026-11-12 기준. 트립꾸 사용자(저장소 주인)와 Claude가 함께 만든 기능을 정리한 문서입니다. 이 문서만 읽고 이어서 작업할 수 있게 썼습니다. 코드 구조의 세부는 [`JOURNEY_개발_인계.md`](./JOURNEY_개발_인계.md)에 있습니다.

## 1. 프로젝트 한 줄 소개

트립꾸(TRIPKKU)는 친구·가족과 함께 여행 일정을 짜는 웹앱(PWA)입니다. 빌드 도구 없는 정적 파일이고 GitHub Pages로 배포됩니다.

- 웹앱: https://gayeon-hong.github.io/tripkku/next/
- 저장소: https://github.com/Gayeon-Hong/tripkku (`main` 에 올리면 1~3분 뒤 자동 배포)
- 지금 쓰는 앱 폴더: `next/` (`index.html`, `app.js`, `style.css`)
- 데이터: Supabase. 여행 하나가 `tripkku_trips` 의 한 행이고, 일정·메모·예산 등은 그 행의 `data`(JSON 문서)에 들어 있습니다.

## 2. 이번에 만든 것

1. **내 캐릭터 꾸미기** — 2등신 3D 캐릭터. 전부 무료.
2. **동선 재생** — 일행 캐릭터가 실제 지도 위에서 일정 순서대로 이동하고, 장소마다 그곳에 맞는 소품·행동·표정을 보여 줍니다.
3. **여행 영상** — 여행 마지막 날부터 버튼이 "여행 영상 만들기"로 바뀌고, 출발 → 모든 장소 → 집 도착 → "여행 끝!" 장면을 빠르게 돌려 영상 파일로 저장합니다.
4. **화면 곳곳의 캐릭터** — 여행 소개 카드(일행), 홈 인사 카드(내 캐릭터), 홈의 여행 카드(일행 얼굴), 초대 창(참여자 얼굴).

## 3. 사용자가 정한 요구사항 (꼭 지킬 것)

대화하며 사용자가 직접 정하거나 고쳐 달라고 한 내용입니다. 앞에서 한 번 거절된 방식은 다시 쓰지 마세요.

### 캐릭터
- **3D로 한다.** 2D(캔버스로 그린 단순 도형)는 "너무 별로"라고 거절됨. 참고 이미지는 머리가 크고 볼륨감 있는 2등신 3D 캐릭터(후드티, 큰 반짝이는 눈).
- **유료화 없음.** 모든 꾸미기는 무료.
- **얼굴형은 "네모·동그라미·세모" 고르기가 아니라** 사람 얼굴 동그라미에서 **조금씩 조절**(슬라이더: 볼 너비, 얼굴 길이, 턱선).
- **머리 모양은 단순하게**: 단발, 긴머리, 파마, 짧은머리, 짧은 파마, 까까머리.
- **앞머리를 따로 고른다**: 있음 / 없음 / 가르마. 앞머리 "있음"은 눈썹 위까지 충분히 내려와야 함("앞머리 너무 없다"는 지적을 받고 고침).
- **눈썹 선택**: 둥근, 일자, 올라간, 진한, 없음.
- **파마**는 큰 공 몇 개가 아니라 작은 뭉치가 촘촘한 모양("파마 너무 별로"를 받고 고침).
- **키**: 보통 / 어린이 / 아기. 아기는 작게(머리 비율은 더 큼).
- **관계와 역할**: 여행마다 친구 / 가족 / 연인을 고르고, 각자 역할(엄마, 아빠, 딸, 아기, 여자친구 …)을 고름. 이름표에 "딸 하린"처럼 표시.
- **전통의상**: 그날 일정의 나라에 맞는 전통의상을 자동으로 입음. 사용자는 **여/남 형태와 색만** 고름(안 입기도 가능). 집 근처에서는 평소 옷.
- **표정이 바뀐다**: 평소(가끔 깜빡임), 미소, 활짝 웃음, 놀람, 윙크, 오물오물, 편안함, 졸림.

### 동선 재생
- **배경은 실제 지도.** 장소 카드를 길로 이은 "보드판"은 거절됨.
- **카메라는 구글 지도처럼**: 먼 이동(비행기, 도시 간)은 멀리서 본 지도로 바뀌어 지나가고, 가까운 곳끼리는 클로즈업을 유지한 채 "직직직" 걸어서 이동.
- **장소에 맞는 소품을 직접 그려서** 보여 준다(성을 보러 가면 성, 크리스마스 마켓이면 트리). 이모지 소품은 거절됨.
- **장소에 맞는 행동**: 트리 앞에서 좋아하며 환호, 식당에서 먹기, 성 앞에서 사진 포즈 등.
- 여행이 끝나면 각자 캐릭터가 인천 → 베를린 → … → 다시 집으로 빠르게 도는 영상.

### 일정 분석과 소품 (2차 요구)
- **"우와 트리다"만 하지 말고 일정을 다 분석**해서 장소마다 다른 소품·말풍선을 쓴다. 같은 종류가 반복되면 차례로 바꾼다(크리스마스: 트리 → 산타 → 가판대 → 눈사람 → 글뤼바인).
- **음식**: 일정에 음식이 특정돼 있으면 그 음식(스테이크, 파스타, 초밥 …), 안 적혀 있으면 그 나라에서 흔히 먹는 음식(서양이면 스테이크·파스타 등), 나라도 모르면 평범한 그릇. "라멘만 나온다"는 지적을 받고 고침.
- **비행**: 화면 전환이 아니라 **지도 위에서** 멀어지며 항로를 따라 날아가고 다시 가까워진다. 지나온 항로가 선으로 그려진다.
- **나라가 바뀌면 국기**: 화면 위 카드(너무 크다 → 띠 → "아예 없어졌다")는 모두 거절. **대표(첫 번째 사람)가 국기를 들고 똑바로 세워 흔든다.**

### 지도·크기 (4차 요구)
- 한 나라 안 이동이 잘 보이게 **도시에서는 지도를 더 확대**(골목 수준), 걷는 동안은 두 장소가 함께 보일 만큼만 잠깐 멀어진다.
- **캐릭터는 작게**(가운데 소품과 정확한 위치가 가려지지 않게). 머무는 동안은 장소 표시 앞쪽에 선다.
- 장소마다 **종류별 아이콘 핀**(음식·카페·볼거리·쇼핑 등 색과 아이콘이 다름)을 지도에 꽂는다. `journey.js` 의 `ICON` 표. 구글 지도 아이콘을 그대로 가져오지는 않고 직접 만든 핀을 쓴다.

### 시간대·날씨·관리자 (5차 요구)
- **일정 시각에 따라** 낮 → 노을 → 밤으로 어두워진다. 밤에는 하늘에 별과 달, 건물 창문·전구가 빛나고, **야경** 일정은 불 켜진 도시 소품.
- **그날 날씨**(Open-Meteo, 지난 날은 기록·16일 안은 예보)를 반영: 비·눈·흐림·안개·뇌우. 날짜 옆에 날씨 표시.
- 장소 이름표가 잘리지 않게 **짧게 요약**하고 시각을 따로 표시(괄호·부연 설명 제거, 앞의 몇 단어만).
- **트립꾸 관리자는 모든 권한**: 모든 여행에서 만든 사람과 같은 권한(참여자 내보내기, 여행 정보 수정·삭제, 누구 캐릭터든 변경). 서버 쪽은 `sql/2026-11-12_admin_powers.sql` 을 Supabase에서 실행해야 열림.
- 여행 만든 사람은 참여자를 내보낼 수 있고, 참여자는 스스로 나갈 수 있다.

### 홈 화면 (3차 요구)
- "메인이 조잡하다" → **여행 목록이 먼저**, 새 여행 만들기는 **버튼**으로 분리(누르면 창), **최근에 연 여행이 위로**.
- **현위치 활용**: 위치를 켜면 홈에 지금 있는 곳·날씨·환율, 여행 카드에 "지금 여기" 표시.
- **환율 계산기**: 현지 금액 → 원화, ⇄ 버튼으로 원화 → 현지 금액도(방향은 기기에 기억).
- 위쪽 **지구 표정 버튼(😊🥰😴😡)을 누르면 캐릭터 얼굴도 같은 표정**.
- 지구 그림은 캐릭터 옆에서 뺐음("조잡하다").
- 지구 캐릭터 등 기존 요소는 바꿔도 된다고 함(홈 인사 카드는 내 캐릭터가 대신함).

### 6차 이후 요구 (2026-11-12)
- **여행 전체 편집**: 이름·여행지·기간·방문 국가 추가/순서. 공항 이동·체크인은 비행이 아니다.
- **이동 일정 글자 분석**: "인천출발바르샤바도착", "ICN-WAW", "바르샤바행", "인천에서 바르샤바로" 등에서 출발·도착 도시를 뽑는다. 600km 넘으면 비행. 같은 곳(150km 안)으로 가는 비행은 비행이 아님(귀국 후 비행기 두 번 타던 문제).
- **도시별 대표 건물을 디테일하게**: 베를린(브란덴부르크 문·장벽·TV 타워·국회의사당·체크포인트 찰리·대성당·전승기념탑·샤를로텐부르크), 프라하(성·카를교·천문시계·틴 성당·화약탑·댄싱하우스), 드레스덴(성모교회·츠빙거·젬퍼 오페라·군주의 행렬), 바르샤바(문화과학궁전·왕궁). 도시 이름만 있어도 그 도시 건물이 차례로 나온다.
- **크리스마스 마켓은 도시마다 다르게**, 드레스덴은 대관람차(회전)·크리스마스 피라미드. **날아가는 산타**는 가끔만(장소마다 약 30%, 같은 영상은 같게). 같은 효과는 무작위로만.
- **진짜 행동**: 식당은 식탁에 둘러앉아 포크로 먹기, 구경은 건물을 바라보며 사진·가리키기·올려다보기, 공연은 무대 앞 반원, 박물관·공원은 흩어져 구경. 장소마다 자리 배치가 다르다.
- **카메라가 역동적으로**: 구경할 때 건물로 다가가 옆으로 훑기 → 다 같이 돌아서 기념사진 → 반대쪽 클로즈업.
- **탈것 창문에 얼굴 빼꼼**: 비행기·버스·기차 창문마다 일행 얼굴이 작게.
- **해 뜨고 지는 시각**을 장소·날짜마다 대략 계산(겨울 베를린은 16시쯤 밤).
- **기본 속도는 느리게**(약 1.6배), 속도 0.5~2.5배 선택. 영상 저장은 재생을 기다리지 않고 빠르게(백그라운드 저장은 웹에서 불가).
- **지도는 예전 범위가 더 좋다**: 타일 범위를 넓혔다가 흐려져서 되돌림(`XR=480,FAR=1380,NEAR=440`).
- **일정표**: 오늘이면 지금 시간대 카드에 일행 얼굴을 **체스 말**처럼 세운다. 카드 옆 3D 장소 그림은 "범용으로 못 쓰니 빼자"로 제거.
- **장소 3D는 계속 추가**: 사진(구글·위키) 방식은 거절. 관리자 화면의 "전용 3D가 아직 없는 장소" 목록을 사용자가 복사해 주면 그때 만든다. 새 여행이 등록되면 관리자 버튼에 숫자 배지.

### 작업 방식
- 사용자는 주로 **휴대폰**에서 대화함. 답은 짧게, 결과 이미지 위주로.
- 코드를 고치면 **바로 GitHub `main` 에 올려 달라**고 함(사용자의 PC가 꺼져 있어도). 클라우드 작업 공간의 저장소 복제본에서 고치고 푸시함.
- 파일을 고치면 `index.html`(와 `journey.js` 안 `journey3d.js` import)의 `?v=` 값을 올린다. 서비스 워커가 새 버전을 알아서 받아 한 번 새로고침한다.
- 공개 저장소: service_role 키·AI 키·OAuth 비밀·토스 서버 키는 절대 커밋하지 않는다.

### 수익화 계획 (단계별 진행 중)
- **1단계 완료(2026-11-12): 쿠폰 서버 기록** — `sql/2026-11-12_coupons.sql`(가입 1장, 새 계정 초대 1장·하루 3·월 10 상한, 저장 때 1장 차감, 같은 영상 재저장 무료, 관리자 무제한). 앱은 `__tripkku.coupon` 으로 호출, 동선 창에 잔액 표시. 결제·워터마크·푸시는 다음 단계.
- 디테일 제작(여행당 3,000원 예정)은 결제 없이 요청→제작→자동 해제 흐름만 있음.
- **영상 만들기·미리보기는 무료**, **저장(다운로드)과 공유만 유료**: 1개당 **1,000원**.
- **무료 쿠폰**: **회원가입하면 1장**, **사람을 초대하면 1장**(저장·공유 1회권).
- **트립꾸 관리자(`tripkku_beta_admins`)는 결제·쿠폰 없이 모든 기능 사용**, 그리고 모든 여행에서 만든 사람과 같은 권한(참여자 내보내기, 여행 삭제·수정, 캐릭터 변경).
- 악용 방지(구현할 때 지킬 것):
  - 쿠폰·결제 내역은 브라우저가 아니라 **서버(Supabase 테이블 + 함수)**에만 둔다. 저장/공유 버튼을 누를 때 서버 함수가 1장을 차감하고 **1회용 토큰**을 돌려주며, 토큰이 있어야 파일을 내보낸다.
  - 무료 미리보기 화면에는 **"TRIPKKU 미리보기" 워터마크**를 넣고, 결제 후 만드는 파일에서만 뺀다(화면 녹화로 우회해도 워터마크가 남게).
  - 같은 영상(여행·범위·속도 같음)을 다시 받을 때는 **추가 결제 없이** 받을 수 있게 서버에 기록.
  - 초대 보상은 **처음 가입한 새 계정이 실제로 여행에 참여했을 때만**, 한 사람당 하루·월 상한을 둔다. 같은 기기·같은 소셜 계정으로 여러 계정을 만들어 스스로 초대하는 경우 지급 안 함.
  - 결제는 토스 미니앱 결제로 연동(`toss-miniapp/`). 웹앱·MS 스토어판 정책은 따로 정할 것.

## 4. 현재 상태

## 5. 파일과 저장 형식

| 파일 | 역할 |
| --- | --- |
| `next/journey.js` | 캐릭터 설정·선택지, 타임라인, 장소 좌표 찾기, 지도 카메라, 2D 덧그리기, 창·버튼, 영상 저장, 화면 곳곳에 캐릭터 넣기 |
| `next/journey3d.js` | Three.js 장면: 캐릭터(`buildAvatar`, `poseAvatar`), 전통의상(`costumeSpec`), 소품(`PROPS`), 지도 장면(`createStage`), 미리보기(`createPreview`), 작은 초상화(`createPortraits`) |
| `next/app.js` | `window.__tripkku` 로 필요한 값만 내보냄(여행·참여자·저장 함수 등), 여행 카드에 `data-trip-id` |
| `next/index.html` | 일정 탭 버튼 `#journeyPlay`, `#avatarEdit` 과 스크립트 태그 |

저장 형식(여행 문서 `data` 안):

```js
data.avatars[userId] = {
  faceW, faceH, jaw,            // -1 ~ 1, 얼굴 조절
  skin, hair, bangs, hairColor, // bangs: full | none | part
  eyes, brows,                  // brows: soft | flat | up | thick | none
  size,                         // adult | kid | baby
  outfit, acc,                  // 평소 옷 색, 소품(glasses | ribbon | cap)
  costume, gender, costumeColor,// 전통의상 on|off, f|m, 색
  role                          // 역할(최대 8자)
}
data.meta.groupType = 'friends' | 'family' | 'couple'
data.geo['장소 이름 소문자'] = [위도, 경도]   // 못 찾으면 0
```

내 캐릭터는 기기의 `localStorage['tripkku-next-avatar']` 에도 저장되고, 내 캐릭터가 없는 여행을 열면 한 번 자동 적용됩니다.

## 7. 남은 일 (우선순위 순)

1. **MS 스토어 출시 계획 + 푸시 알림**(사용자 요청, 아직 시작 안 함): PWABuilder로 MSIX 포장, Partner Center 등록. 푸시는 Web Push(VAPID) + Supabase 테이블(`push_subscriptions`) + Edge Function으로 보내기. 보낼 것: 새 여행 등록 → 관리자, 일정 변경·초대 → 일행. 앱 쪽 수신은 `sw.js` 에 이미 있음.
2. **수익화(토스)**: 위 3장 계획대로. 만들기 무료, 저장·공유만 유료, 관리자 제외, 서버 쿠폰·워터마크.
3. 관리자 화면의 "전용 3D가 없는 장소"를 보고 랜드마크 계속 추가(`journey3d.js` `PROPS` + `journey.js` `RULES`·`CITY_SIGHTS`·`ICON`).
4. 캐릭터·전통의상 품질(후드티·머리카락 결, 의상 무늬·고증).
5. 좌표가 틀린 장소를 직접 고치는 화면, 길 따라 걷기(경로 API).
6. 일행이 따로 행동하는 일정, 영상 배경 음악, 저사양 휴대폰 옵션.
