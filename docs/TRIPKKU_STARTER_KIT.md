# 트립꾸 스타터 키트 · 재사용 부품과 수익화 경로

이 문서는 트립꾸 코드에서 **다른 앱에 그대로 옮겨 쓸 수 있는 부분**과, 그걸로 돈이 되는 형태 세 가지를 정리한 것입니다.
(2026-11-11, `next/app.js` 기준)

---

## 1. 그대로 떼어 쓸 수 있는 부품

### ① 공동 편집 저장 엔진 — `saveTrip()`
- 리비전 번호로 낙관적 잠금을 하고, 충돌하면 최신본을 다시 읽어 **내 변경만 다시 적용**합니다(최대 5회).
- 저장 요청은 큐로 직렬화되어, 연속 클릭에도 순서가 뒤섞이지 않습니다.
- 응용: 가계부, 공동 체크리스트, 팀 보드, 모임 일정.

### ② 초대 링크 · 멤버 권한 — `createShareInvite()`, `joinTrip()`, `removeTripMember()`
- 32자리 토큰, 만료·사용 횟수 제한, 소유자/편집자 구분.
- 초대 링크 하나로 상대는 로그인만 하면 참여. 이메일·계정 ID를 주고받지 않습니다.

### ③ AI 호출 규약 — `functions/tripkku-ai` + `aiCall()`
- 서버에서만 키를 쓰고, 클라이언트는 JWT로 호출.
- 기능별(kind) 분기: `plan` / `chat` / `translate` / `detect-country`.
- 일일 사용량 제한(`tripkku_ai_allow`), JSON 스키마 검증, 실패 시 사용자에게 이유를 그대로 전달.
- 응용: 어떤 서비스든 "AI가 제안 → 사용자가 승인 → DB 반영" 구조에 그대로 이식.

### ④ 개인정보 경계 — RLS 패턴
- 같은 여행 안에서도 `member_finances` 는 본인 행만 읽힙니다.
- 개인 예약파일은 스토리지 경로가 `{user_id}/{trip_id}/...` 로 고정되어 있고, 서명 URL 90초 만료.
- 응용: 부부 가계부, 팀 비용 정산, 상담 기록처럼 "같은 그룹, 다른 가시성"이 필요한 모든 곳.

### ⑤ 화면 부품
- `renderSchedule()` 타임라인 + 시간 겹침 확인 다이얼로그
- `renderBudget()` 다중 통화 예산(환율은 Frankfurter 일일 고시)
- `translateText()` 음성 인식·낭독이 붙은 번역 패널
- 지구 캐릭터 테마(`applyTheme()`, 낮/밤 × 표정 4종)

## 2. 수익화 경로 세 가지

### A. 스타터 키트 판매 (가장 빨리 현금이 되는 길)
- 위 ①~④를 `starter/` 폴더로 분리해 "로그인 + 초대 + 공동 편집 + AI 제안" 템플릿으로 판매.
- 국내외 모두 수요가 있는 형태: Supabase + 카카오 로그인 조합은 한국어권에서 특히 자료가 적습니다.
- 필요한 일: ① 부품 분리(2~3일) ② 예제 앱 1개(가계부 추천) ③ 문서·스크린샷 ④ 판매 채널(레몬스퀴지·Gumroad·크몽).
- 가격대: 1만~3만 원(개인) / 10만 원대(팀 라이선스). 첫 달 목표는 판매량보다 "설명이 필요 없는 템플릿" 완성.

### B. PWA 미니앱 배포
- 트립꾸 웹앱은 이미 PWA입니다. 홈 화면 설치 → 오프라인 일정 → 여행 중 사용.
- 앱스토어 심사 없이 링크로 배포하고, 여행 커뮤니티(네이버 카페·디시 여행 갤·레딧 r/travel)에 "무료 베타"로 뿌리는 방식이 현실적입니다.
- 수익은 후속: AI 추천 일일 무료 3회 → 추가는 광고 시청 또는 소액 결제(토스 인앱결제 정책 준수).

### C. 앱인토스(토스 미니앱)
- 토스 사용자에게 바로 노출되는 채널. 다만 **토스 로그인만** 허용되고 외부 결제 링크도 제한됩니다.
- 필요한 일: `toss-miniapp/apps-in-toss.config.ts` 의 `appName` 확정 → `npx ait build` → 콘솔 업로드 → 샌드박스 테스트 → 검수.
- 아직 없는 것: `TossAuth.login()` 코드를 토스 서버에서 검증하는 `/toss/session` 서버, 계정 연결 UI, 약관·개인정보 처리방침.
- 결론: A나 B로 사용자를 먼저 모은 뒤 C로 넓히는 순서가 안전합니다.
