3. Supabase > Edge Functions > Deploy a new function > Via Editor.
   Function name MUST be trip-ai.
   Paste code from supabase/functions/trip-ai/index.ts and Deploy.
   Test after login at https://gayeon-hong.github.io/tripkku/ .
4. Important: click '+ 새 여행 만들기' AFTER login, not edit only the offline demo.

5. In the '말로도 일정 편집!' chat, type e.g. '2일차 카페 추가' and click '보내기'.
   If Gemini returns a proposal, read it and explicitly approve the confirmation dialog.
   Approving writes through the existing RLS-protected Supabase repository.
6. If errors occur: Supabase Edge Functions > trip-ai > Logs; browser F12 > Network > trip-ai.

SECURITY / LIMITATIONS
- Do not place Gemini API key in config.js or GitHub.
- Existing code uses multiple separate DB operations (not an atomic transaction); partial updates are possible if later changes fail. Back up data and test with a disposable trip before real use.
- The current UI uses a browser confirm dialog, not custom Approve/Cancel buttons.
- Verify role and RLS policies for each table before making this public.
- Runtime service and API key are not connected in this analysis; production execution has NOT been tested.
- There is an existing SQL owner/read policy discrepancy in older sql/schema.sql; do NOT overwrite your now-fixed policy by executing that whole schema.
