Tripkku Gemini 시간·동선 고려 일정 편집 v5 (2026-10-27)
========================================================

문제 원인
- 기존 Supabase trip-ai 프롬프트가 '오후', '점심 이후' 같은 모호한 time_label을 보존하라고 지시하여 시간순 정렬은 되더라도 이동 시간 계산 없이 저장됐습니다.

이번 변경
1) Gemini는 앞뒤 일정·방문 지역·추정 이동 여유·운영시간을 고려해 HH:mm–HH:mm 시간대를 제안합니다.
2) Edge Function이 실제 저장 전 중복 시간·이동 여유·일부 명소 운영시간을 검사합니다. 위반하면 AI가 한 번 재제안하며, 그래도 어렵다면 자동 승인되지 않습니다.
3) AI 일정에 '📍 장소' / '🚏 출발' 정보가 있으면 상세 일정에 '🧭 길찾기' 링크를 표시합니다.
4) 사용자 승인 전에 다른 멤버가 일정을 바꾸면 재요청을 안내합니다.
5) A/B 플랜과 여러 날짜에서 기존 일정 수정·삭제/이동도 제안할 수 있습니다.
6) 브라우저 캐시 버전을 갱신합니다.

적용 순서
A. GitHub의 tripkku 저장소 최상위 폴더에서 아래 다섯 파일을 같은 이름으로 교체, Commit changes:
   app.js
   ai.js
   index.html
   style.css
   sw.js
   ※ config.js, collab.js, Supabase DB는 변경하지 않습니다.

B. Supabase → Edge Functions → trip-ai → Code(Edit)에서
   supabase/functions/trip-ai/index.ts
   파일 전체 내용을 붙여넣고 Deploy/Save합니다.
   ※ 함수 이름은 새로 만들지 않고 기존 'trip-ai'를 업데이트합니다.
   ※ GEMINI_API_KEY Secret은 그대로 유지하며, JWT 검증은 켠 상태로 둡니다.
   ※ 별도 SQL 실행 필요 없음.

C. GitHub Pages 배포 완료 후 Ctrl+Shift+R로 새로고침합니다.

D. 테스트용 여행에서 먼저 확인합니다.
   '1일차 기존 일정과 이동시간을 고려해 근처 카페 방문을 추가해줘.'
   'B안 일정 전체를 보고 시간이 오후로 표시된 항목을 재배치해줘. 이동시간이 부족하면 대안을 알려줘.'

중요한 한계
- Google Maps Routes API 같은 실제 길찾기 소요시간 API는 아직 연동되지 않았습니다.
  기본은 Gemini의 일정 검토와 보수적인 지역 간 이동 버퍼(계획용 추정치)입니다.
  교통편·정확한 거리·환승 시간·영업시간은 링크에서 최종 확인하세요.
- '오후'로 이미 저장된 항목은 파일 배포만으로 자동 변경되지 않습니다. AI에 재배치를 요청하거나 삭제/수정해야 합니다.
- AI의 잘못된 시간 제안은 자동 적용되지 않으며, 승인/취소 창을 거칩니다.
- 여러 사용자가 동시에 쓰는 환경에서 DB 수준의 완전한 원자적 충돌 방지는 별도 RPC/트랜잭션 설계가 필요합니다.
- 실제 Gemini/Supabase 배포는 여기서 실행하지 않았습니다. 로컬 함수 테스트 및 JS/TS 구문/타입 검사를 통과했습니다.
